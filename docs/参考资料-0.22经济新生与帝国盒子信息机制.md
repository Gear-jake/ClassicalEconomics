### 1.2 货币替换的关键手法：**别名两个方法，整套货币就换掉了**

- 0.22.9 里**所有**对城市金币的读写都经过 `CityStorage.get(string)`（L213）与 `CityStorage.change(string, int)`（L266）——9 处触点无一例外（建筑产金、造兵门槛 `City.cs:1545`、装备成本 `CityStorage.cs:205`、建造扣费…）。
- 所以补丁只做一件事：**Prefix 这两个方法**，命中金币资源时改写账本、返回 `false` 跳过原版。
- 结论：**"别名收口点"比"逐个替换调用点"省一个数量级**（他们因此删掉了两个建造补丁）。
- 安全线：`配置关 / 账本没开 / 拿不到城市` → 一律 `return true` 走原版。
- 性能细节：`CityStorage._city` 是 private → 用 `AccessTools.FieldRefAccess<CityStorage, City>(...)` **缓存反射委托**（"每帧高频调用，不能每次 Traverse"）。
`[已核实：Patches/PatchCurrencyAlias.cs:7-60]`

### 1.3 账本（SQLite）的三条纪律

`LedgerDb` 头部逐字写着（照抄自"日记与族谱"的血泪教训）：

1. **只增不删**：快照语义（`INSERT OR REPLACE` 同一主键），`history` 只追加，不做"清空重导"；
2. **读路径能自愈**：库丢了/坏了，从当前世界状态重建（每年都写 → 最多损失一年）；
3. **绝不拿内存当权威**：只把"已经算出来的快照"写盘；内存为空时不覆盖。
   另有：`PRAGMA journal_mode=WAL` + `synchronous=NORMAL`；`FlushThreshold=1500` 变更就先刷一次（限制崩溃丢失窗口）；分页装载 `LoadPageSize=2000`（失败回退全量）。
   `[已核实：Core/LedgerDb.cs:9-24, 88, 142-144]`

**落盘位置**：默认 `persistentDataPath\经济新生\ledger_<worldKey>.db`，但**如果拿得到存档目录就搬进存档目录**（`er_ledger.db`，带 legacy 迁移日志）——即"**与存档解耦但可随档走**"。
`[已核实：RebirthPaths.cs:9, 28-44, 61-103]`
**原生库引导**：游戏自带 `sqlite3.dll`（3.8.6）优先；否则把系统 `winsqlite3.dll` 复制到模组缓存改名 `sqlite3.dll`；必须在任何 `SQLiteConnection` 之前 `EnsureLoaded()`（因为 `SQLite.cs` 里 DllImport 名固定为 `"sqlite3"`）。
`[已核实：Core/SQLiteNative.cs:11-40]`

### 1.4 年度货币循环的**顺序**（这是最该整体搬过来的一节）

`AnnualCycle.OnYear` 的调用顺序（注释即依赖说明）`[已核实：Core/AnnualCycle.cs:60-167]`：

1. `ResourceCap.ApplyAll()` — 资源上限幂等刷
2. 门槛：世界就绪 / **有城市**（否则跳过，避免启动期刷一屏 0）/ 年号未结算
3. `LedgerDb.EnsureOpen()`
4. **M1 只读镜像**：每国快照（人口/城市/税基/财富/稳定）→ 写 history + 建账户占位 → 写 meta → `Flush`
5. 年初清零：`CurrencyEngine.ResetYearCounters` / `EstateEngine.ResetPieceWages` / `PersonalSpending.ResetYearCounters` / `CorruptionEngine.ResetYearCounters` / `CurrencyEngine.ResetPersonIncome`
6. `EstateEngine.RunKingAi()` — 国王 AI（**用去年状态**定政策）
7. `EstateEngine.OnYear()` — 阶层/控制力/税基/财富（**必须早于市场**）
8. `EstateEngine.EndowCitiesIfNeeded()` — 初始货币投放（每城一次性）
9. `EstateEngine.PayPieceWages()` — 计件工资（城市→劳动者，单价=本地价格，守恒）
10. `EstateEngine.CollectConsumptionSpending()` + `PersonalSpending.CollectHousingFees()` — 消费/住房回收（个人→城市）
11. `CurrencyEngine.SeedFromVanillaIfNeeded()` — 一次性把原版仓库金币折算成账本余额
12. `EstateEngine.CollectTaxes()` — 税收入国库（账本）
13. `EstateEngine.CollectEstateWealthTax()` — 个人按阶层征税 → 国库
14. `EstateEngine.PayWages()` — 发薪（国库→个人，**必须在收税之后**）
15. `EstateEngine.PaySoldierWagesAnnual()` — 军饷（城市优先 + 国库补助）
16. `StatusEffectEngine.ApplySoldierMoraleDebuff()` — 缺饷 debuff（按本年**实发比例**，取消每期全城扫描）
17. `CorruptionEngine.OnYear()` — 市长/国王贪污（城市/国库 → 个人）
18. `StabilityEngine.OnYear()` — 稳定度（用 M4 阶层份额算税率压力）
19. `MarketEngine.OnYear()` — 区域价格（用 M4 的阶层需求）
20. `TradeNetwork.SettleYear()` — 陆路贸易（**用刚更新的价格**）
21. `TradeWar.RunYear()` — 关税/禁运/敌意/宣战理由
22. `Caravan.EnsureVisibleCaravans()` — 少量可见商队
23. `CurrencyEngine.FlushDirty()` — 年度结算后一次性批量落盘
24. 生产统计**先取快照**再 `ResetYearCounters()`（他们踩过坑：先重置 → 日志里产收永远是 0）
25. Verbose 一行汇总日志

一句话概括资金流向：**投放（初始/工资）→ 回收（消费/住房）→ 征税（个人→国库）→ 再分配（发薪/军饷）→ 损耗（贪污）→ 定价 → 贸易**。

### 1.5 阶层 / 控制力 / 税基 / 财富模型（M4）

- **阶层**：贵族（`King`/`Leader` 职业）/ 市民（工匠类职业）/ 平民（其余）/ 士兵（单列）。每阶层有：**应税能力**（贵族 240 / 市民 120 / 平民 60 / 士兵 80）、**税率**（5/15/20/8 %，运行时可变 → 权能可调）、**容忍度**（5/10/15/12 %）。
  `[已核实：Core/EstateEngine.cs:26-46, 389-392]`
- **控制力（EU5 式首都临近度）**：首都 = 1.0；其他城市按**城市图 BFS 跳数**（同岛邻接，距离阈值 80）→ `proximity = clamp(100 − hops×18, 0, 100)` → `control = clamp(proximity×0.0075 + 0.20 + 忠诚±0.05 + 驻军±0.05 − 动乱0.05, 0.05, 1.0)`；每年每国算一次并缓存。期望曲线：首都 100% → 1 跳 87% → 2 跳 73% → 3 跳 60% → 4 跳 46% → 5 跳 33% → 6+ ~25%。
  `[已核实：Core/EstateEngine.cs:7-27, 44-82]`
- **税基** = Σ(阶层人口 × 该阶层应税能力) × 控制力；
  **财富** = Σ(城市仓库各资源 × 该区该资源价格)（**市场价值口径**，直接复用 M3 价格）。
- **价格**：按原版连通块分区（`city.getTile().region`）；`price = base[tier] × clamp((需求/供给)^弹性, 0.3, 3.0)`，再做年平滑 `0.7×旧 + 0.3×新`；供给 = 区内存量之和，需求 = 区人口 × 分档系数。
  `[已核实：Core/MarketEngine.cs:7-30]`
- 政策：**王国政策 + 城市政策两套**（玩家可调），国王 AI 每年定一次。
  `[已核实：Core/EstateEngine.cs:292-388]`

### 1.6 其他成体系的机制（可择要移植）

- **贸易**：`TradeNetwork`（城↔城/国↔国真实钱货流动）/ `TradeCargo`（跨城货物）/ `TradePolicy`（每国关税档位 + 禁运名单 + 敌意）/ `TradeWar`（AI 自动发起、**可当宣战理由**）/ `Caravan`（少量可见商队：抽象为主 + 少量实体，挂在 `MapStats.updateWorldTime` 之后驱动）。
- **腐败**：`CorruptionEngine` —— 市长与国王中饱私囊（城市/国库 → 个人）。
- **军饷与士气**：`PatchMonthTick`（军饷**按月**发，原来只在年度发一次）/ `PatchRecruitmentGate`（城市资金 < 6 个月军饷储备 → 阻止招兵）/ `StatusEffectEngine`（缺饷 debuff，仿 K mod 骑兵状态机制）。
- **继承**：`InheritancePatches` —— 人/城/国的"死钱"盘活（守恒 Transfer），确实无人可继承才销毁。
- **资源上限**：`ResourceCap`（并自两个"设置资源上限"模组）。
- **对外 API**：`Api/EconomyApi.cs`（供别的模组查账本余额 / 触发权能）——**我们将来也能给别的模组一个只读经济 API**。
- **世界稳定 ID**：`Core/WorldId.cs` —— 注释里明写"照搬（我们的）古典经济学已验证的做法"（我们的 `WorldIdentity.cs`）。
- **UI**：`UI/UiSkin.cs`（EU4 风格像素皮肤）/ `DraggablePanel`（三面板共用外壳：国家政策 / 城市政策 / 本地市场）/ `UiResize`（面板独立宽高，注释写"移植自古典经济学"）/ `ControlMapLayer`（控制力地图层：Prefix 掉原版图层绘制）/ 面板挂在**城市窗口一侧**。

## 2. 帝国盒子（0.51，`Mods\EMPIRECRAFT(帝国盒子)`）："增加信息"的四种方式

### 2.1 小数据 → 原版 `custom_data_*` 容器（最省事）

本体 `BaseSystemData.cs:17-29` 给**每个实体数据**都备了 5 个可序列化容器：

```csharp
public CustomDataContainer<int>    custom_data_int;
public CustomDataContainer<long>   custom_data_long;
public CustomDataContainer<float>  custom_data_float;
public CustomDataContainer<bool>   custom_data_bool;
public CustomDataContainer<string> custom_data_string;
```

`CustomDataContainer<T>` = `[Serializable]` + `[JsonConverter(typeof(CustomDataContainerConverter))]` + 池化 `Dictionary<string,TType>` → **随游戏存档自动保存**，我们不用写一行存档代码 `[已核实：CustomDataContainer.cs:8-22]`。

帝国盒子的用法 `[已核实]`：
- 每单位的"历史记录"字符串：`data.custom_data_string[CustomDataType.empirecraft_history_record.ToString()] = ""`（`ActorPatch.cs:634-638`，**懒初始化**：先判 `== null` 再建容器）
- 家族杂项标志：`family.data.custom_data_bool["has_city_pre"]`（`OverallHelperFunc.cs:443-455` 用 `.dict` 或索引器）
- key 用**枚举名当命名空间**（`Enums/CustomDataType.cs` 目前只有一个值 `empirecraft_history_record`）。

> 我们的用法建议：给"经济"建一个自己的 key 命名空间（如 `ce_*` 前缀或 `CEDataType` 枚举），只放**小标量**（某城税基缓存、某国政策标记）；大数据不要塞这里（会膨胀存档）。

### 2.2 每实体扩展对象 → `ConditionalWeakTable`（运行时 + 自己序列化）

`GameClassExtensions/`（14 个文件）：`ActorExtension` / `CityExtension` / `KingdomExtension` / `ClanExtension` / `FamilyExtension` / `ReligionExtension` / `BookExtension` / `WarExtension` / `MetaTypeExtension` + `ExtensionBase` / `ExtensionManager` / `ExtraDataBase`。

```csharp
public static class ExtensionManager<TKey, TData> where TKey : NanoObject where TData : class, new()
{
    public static ConditionalWeakTable<TKey, TData> _table = new();
    public static TData GetOrCreate(TKey key, bool isSave = false) { ... }   // isSave=true → 只取不建
    public static void Update(TKey key, TData data) { ... }
}
public class ExtraDataBase { public long id { get; set; } }   // 存档用 id
```
配合扩展方法 `entity.GetOrCreate<TKey,TData>()` / `entity.SyncData(data)` / `entity.RemoveExtraData<...>()` / `ExtensionBase.Clear<...>()`
`[已核实：ExtensionManager.cs:11-32, ExtensionBase.cs:5-32, ExtraDataBase.cs:6-9]`

**为什么这是关键**：数据**挂在实体对象身份上**，实体被销毁/换世界时随 GC 消失 → **天然没有"跨局残留"问题**（我们现在是静态 `Dictionary<long,...>`，必须靠 `ResetAllEngines` 手工清）。代价是要自己写序列化（EC 就写在侧车 JSON 里）。

### 2.3 大数据 → 存档目录里的侧车 JSON（带版本迁移）

- 文件名常量：`EmpireCraftSaveFileName = "EmpireCraftModData.json"`；`CurrentSaveDataPath` 从存档根目录拼出来。
- 根模型 `SaveData`：**按实体种类一个 List**（`actorsExtraData` / `kingdomExtraData` / `cityExtraData` / `clanExtraData` / `bookExtraData` / `warExtraData` / `religionExtraData`）+ 帝国/头衔/文化（制度、科技、绑定）+ `all_history` + 封建世系 + 联盟 + 官职 + 若干开关 + **`public int mod_version = 0;`**
  `[已核实：Data/SaveData.cs:20-49]`
- 载入流程：`LoadAll(loadRootPath)` → 先 `ResetWorldState()` 各子系统 → 文件不在就"初始政权"兜底 → `JsonConvert.DeserializeObject<SaveData>` → **`NormalizeSaveData`**（字段归一）→ 各子系统 `ImportStates(...)` → `isOldSave = saveData.mod_version < ModClass.MOD_DATA_VERSION` → 旧数据迁移（`FactionRatioConverter` 丢弃无法识别的旧派系占比并**记警告**）→ 用 `getID()` 建 `ToDictionary` 索引再逐项绑定
  `[已核实：Data/DataManager.cs:35-80]`
- **存档挂钩点**（EC 用的是自己的方法名，不是原版钩子）`[已核实：GamePatches/SaveManagerPatch.cs:29-53]`：

| 原版目标 | 时机 | 用途 |

## 4. 对我们经济重构的直接含义（备料，不是方案）

1. **"收口点替换"优先于"逐点替换"**：0.51 的城市金币只有 `getResourcesAmount` / `takeResource` 两个收口 → 若要做"账本式经济"，这是最省的接管点（0.22 已验证只需 alias 两个方法）。
2. **钱的口径要一次说清**：0.51 的钱 = Actor `data.money`（0..99999 + `loot`）+ 城市资源 `gold`，**没有国库**。我们现在的 `GlobalGDP`（Σ Actor 钱）与"城市资源"是两套；重构时必须先定义"我们要统一到哪个口径"（0.22 的答案是：账本为唯一货币，原版仓库只是别名视图）。
3. **每实体数据用 `ConditionalWeakTable` 而不是 `Dictionary<long,...>`**：直接消灭"跨局残留 + 手工 Reset"这一类 bug（我们现在 `ResetAllEngines` 就是在还这笔债）。
4. **侧车 + 版本号 + 只增不删**：0.22 的 SQLite 三纪律与 EC 的 `mod_version` + `Normalize` + 旧数据迁移日志，都是我们存档层的现成模板；0.51 还多给了 `custom_data_*`（小数据零成本）。
5. **年度管线应显式声明依赖**：0.22 的 22 步顺序带依赖注释（"必须早于市场"、"必须在收税之后"）——正是我们 `AnnualPipeline` 现在缺的那层文档；重构时可以把顺序 + 依赖做成一个显式表。
6. **先只读镜像，再接管**：M1 只读镜像 + 关开关与 vanilla 逐项一致的回归门禁，是"大改经济却不炸游戏"的落地方式，与我们"门禁即规格"的既有文化天然合拍。
