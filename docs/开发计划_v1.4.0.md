# ClassicalEconomics v1.4.0 开发计划：王国抉择事件系统 + 事件面板重制

> 定稿日期：2026-09-05。经 grill 三轮面试定案（Q1-Q14）。范围：① 抉择事件系统（玩家国+AI 国）② 经济事件面板重制 ③ 三个既有性能缺陷修复。目标版本 1.4.0。

## 0. 决策记录（grill 定案）

| # | 决策 | 定案 |
|---|---|---|
| Q1 | 事件归属 | 玩家国 + AI 国都出事件；AI 按国性自动决策 |
| Q2 | 触发机制 | 混合：事件带前置条件过滤 + AnnualPipeline 新 Events 阶段年度抽签；每国每年最多 1 个；全局冷却防刷屏 |
| Q3 | 呈现 | 独立非模态小窗（可拖走、不暂停）+ 内阁"待决事件"区；超时自动执行保守选项 |
| Q4 | 后果深度 | 零新引擎字段：全部组合现有通道（金库 TrySpend/AddTreasury、居民金币转移、动荡积累、幸福特质、外交好感） |
| Q5 | 规模 | 首发 ≥16 个事件 / 6 族（财政/天灾/宫廷/军事/民生/外交），每族"好/坏/两难"齐全 |
| Q6/Q7 | 数据形态 | **结构**进 events.json（id/族/条件/选项/后果/超时/fallback）；**文本**仍走 Locales/*.json 四语键（键集门禁白拿） |
| Q8 | 六族 | 财政、天灾、宫廷、军事、民生、外交 |
| Q9 | 超时 | 每事件声明 timeoutYears（1~3，天灾短宫廷长）；fallback 选项序号声明在事件里；AI 国无超时（年度即决） |
| Q10 | 频率配置 | 3 个新配置键：玩家国事件概率 / AI 国事件概率 / 全局冷却年数 |
| Q11 | 加载失败 | fail-open：events.json 缺失/损坏 → 空池 + 警告一次，主系统照常 |
| Q12 | AI 呈现 | AI 国不弹窗：年度结算立即决策，结果只进事件流 |
| Q13 | 面板组织 | 过滤 chips（全部/抉择/国家·战争/经济·民生）+ 按年折叠（默认展开最近 3 年）+ 单列时间线 |
| Q14 | 条目密度 | 紧凑单行（年+国+描述），抉择事件可点击展开长描述 |

## S1：事件数据层

### S1-1 events.json（模组根目录，随包发布）
Schema（手写轻量解析器，无外部依赖，加载一次缓存）：
```json
{ "events": [
  { "id": "ev_drought",
    "family": "disaster",            // finance|disaster|court|military|civil|diplomacy
    "minYear": 3,                     // 最早可触发年
    "conditions": { "maxTreasuryRatio": 0.3, "minGini": 0.5, ... },  // 全部可选，AND 组合
    "timeoutYears": 1,
    "fallback": 0,                    // 超时执行的选项序号
    "options": [
      { "key": "ev_drought_opt1",
        "cost": { "treasuryRatio": 0.2 },          // 金库支出（可缺省）
        "effects": { "unrestDelta": -0.05, "happinessTraitDays": ..., "goodwill": 10, ... },
        "styleWeights": { "militarist": 1.5, "pacifist": 0.5 }       // AI 国性权重（可缺省=1）
      }
    ],
    "cooldownYears": 10               // 同事件再触发冷却
  } ] }
```
- 解析失败/缺文件 → 空池 + `Debug.LogWarning` 一次（Q11-A fail-open），不影响经济模拟
- 冷却计数与"每国每年最多 1 个、全局并发上限"一起由运行时管理，不写进 JSON

### S1-2 文本键（Locales ×4）
- 每事件：`ev_<id>_title` / `ev_<id>_desc` / `ev_<id>_opt{0..N}` / `ev_<id>_opt{0..N}_desc`
- 每后果：结果横幅键 `ev_<id>_result{0..N}`（带 {0} 金额等占位）
- 估算新增 ≈16×(2+3×2+3) ≈ 208 键/语言 ×4；`Test-LocalizationCoverage` 白拿键集校验

### S1-3 事件运行时（新 `Core/DecisionEvents.cs`）
- `Load()`：模组加载时解析 events.json（一次）；`Reset()`：新图清空
- `EvaluateYear(int year)`（主线程，AnnualPipeline 新阶段调用）：
  1. 到期检查：挂起事件 timeoutYears 到 → 执行 fallback 选项
  2. 每国抽签：条件过滤（读 EconomyEngine.KingdomStats 纯数据 + NationEngine 主线程状态）→ 概率判定 → 冷却/全局上限过滤 → 入挂起（玩家国）或即决（AI 国按 styleWeights 加权随机）
  3. 全部 O(K×E)，K=王国数、E=事件数(16)，每年一次，微秒级
- `Choose(optionIndex)`：玩家选择入口（UI 调）；执行后果 → 事件流横幅 → 清挂起
- **后果通道**（Q4-A，全部现成 API）：`NationEngine.TrySpend/AddTreasury`、`GameHelpers.DeductCoins/AddPositiveMoney`、`UnrestEngine` 特质、`EraEngine` 幸福特质、`NationDiplomacy` 好感
- 挂起池：仅玩家国事件；`List<PendingEvent>`（复用缓冲，上限 8）

## S2：调度与存档

### S2-1 AnnualPipeline
- AnnualStage 枚举 `Nation` 之后、`Snapshot` 之前插 `Events`（枚举尾部追加新值，**不重排既有值**——Test-StagedPipeline 的阶段序断言与存档兼容性都依赖顺序稳定）
- RunStage 新 case 调 `DecisionEvents.EvaluateYear(year)`

### S2-2 存档（扩展现有 NationSave 或平行 `EventSave`，同机制）
- `rb_ev_pending`：挂起事件（`id|elapsedYears;...`）
- `rb_ev_cooldown`：事件冷却（`id:readyYear;...`）
- `rb_ev_lastGlobal`：全局上次事件年
- 读档恢复 + 每键 try-catch + 失败回退本局记忆（与 LawSave/NationSave 同哲学）

## S3：UI 三件套

### S3-1 事件抉择小窗（新 `UI/EventChoiceWindow.cs`，FloatingWindow 同款）
- 非模态、可拖、不暂停；标题=事件名，正文=desc，选项按钮竖排（含费用与效果摘要行）
- 顶行倒计时"剩余 X 年"（游戏年粒度，随年度刷新，**无每帧计时器**）
- 多个挂起事件堆叠显示（当前事件 + "还有 N 件待决"切换）
- 弹出时机：**Snapshot 阶段后**（收尾 UI 原子尾随 WriteCycleSnapshot 之后统一弹），不在管线中途造 UI

### S3-2 内阁"待决事件"区（CabinetWindow 财税页顶部）
- 挂起事件 ≥1 时显示行（名称+剩余年+"处理"按钮 → 打开小窗）
- 无挂起时不占位（零开销）

### S3-3 事件面板重制（EventWindow，修复可读性）
- **废除一行 3 条挤压排版** → 单列时间线（Q14-A 紧凑单行）
- 顶部过滤 chips：全部 / 抉择 / 国家·战争 / 经济·民生（`family` 归类既有事件类型）
- 按年折叠分组：默认展开最近 3 年，更早的按年收起可点开
- 抉择事件条目可点击展开长描述（opt desc）

## S4：三个性能缺陷修复（本次回溯抓到）

1. **事件窗重建策略（既有缺陷，按"不渲染不调用"原则重做）**：现状是 `EconomyUI.RefreshOverview` 每次调用（含认领后每秒实时路径）都 `EventWindow.RefreshNow()` 整窗重建 160 条。修复为**三档触发**：
   - **隐藏时**：`RefreshOverview` 完全不触碰事件窗，零调用零开销；
   - **打开时**：`Toggle()/Show()` 渲染一次（打开即最新）；
   - **打开期间**：每个游戏年渲染一次（挂在年度快照尾 `WriteCycleSnapshot` 之后——事件内容本来就按年产生，重建节奏=内容节奏，常开窗口每年最多重建一次）；玩家主动操作（切过滤/展开年份/点击展开长描述）即时重建。
   - 新事件在窗口打开期间到达**不触发重建**，下个年度边界自然出现（事件流数据层不受影响）。
   - **预计消除实机最大的 UI 重建热点之一，常开场景从"每秒重建"降为"每年重建"。**
2. **事件流容量冲击（v1.4.0 新增风险）**：AI 国事件全部进事件流后，MinorCapacity=60 会被高频 AI 事件冲刷掉有价值的经济事件。修复：AI 抉择结果记为 Major 类（容量 100，本就低频）；同时 Minor 60→90（内存增量 ≈30×EventEntry，可忽略）。
3. **JSON 重复解析（设计期规避）**：解析仅发生在模组加载一次，运行期零 IO 零解析；挂起/冷却状态全内存 + 存档时序列化（saveSave 前缀，低频）。Events 阶段每帧预算内 O(K×E)，无分配（条件评估用 struct 栈缓冲）。

其余核对：新阶段不动 Test-AllocHygiene 锚区（BeginCycle..ComputeGini 不变）；事件小窗非每帧路径不在分配门禁范围；四语键批量加入后键集门禁自动覆盖。

## S5：配置 + 门禁 + 发布

- **3 个新配置键**：`event_chance_player`（默认 0.35，0~1）、`event_chance_ai`（默认 0.15，0~1）、`event_cooldown_years`（默认 3，1~10）——default_config + UnrestConfig + ConfigCallbacks + 四语 + Test-ConfigDocs 行
- **新门禁 `Test-DecisionEvents.ps1`**：events.json 每事件 ≥2 选项、有 fallback、timeoutYears∈[1,3]、family 合法；Locales 四键组齐全；DecisionEvents 零 IO（除 Load）；AnnualStage 枚举 Events 在 Nation 与 Snapshot 之间
- **事件清单（16 个首发草案）**：
  - 财政：国库亏空、税吏贪腐、铸币短缺、富商请愿
  - 天灾：大旱、蝗灾、地震余波、严寒
  - 宫廷：王室婚宴、权臣干政、继承争议、密探告发
  - 军事：边军索饷、雇佣兵违约、战俘赎回、凯旋庆典
  - 民生：粮价骚乱、行会请愿、瘟疫防治、流民涌入
  - 外交：邻国勒索、流亡贵族、联姻提议、边境摩擦
- 发布：版本 1.3.0→**1.4.0**；README×4 与四语 Steam 描述加"抉择事件"亮点；打包三方哈希验证；git 提交推送；`gh release create v1.4.0`

## 交付后实机验证点
- 挂起事件跨存档恢复；超时自动执行 fallback；AI 国事件出现在事件流且按国性决策
- 事件窗：过滤 chips 生效、按年折叠、单行排版；**常开事件窗每年只重建一次**（隐藏时零调用），长挂机帧率平稳
- 三个频率配置键调 0 → 全年无事件；events.json 改坏 → 警告一次且经济照常
