## 0. 一句话定位

`古典经济学` 是一个 **旁路观察 + 治理叠加层**：采集全种族财富算出 GDP/基尼/CPI，在此之上叠加经济周期、社会动荡、劳动价值、灾害冲击、银行信贷、法典国策、统治者性格与抉择事件。

**它不是经济接管层。** 除了 `BankEngine`/`NationEngine` 的真实金币流，其余全部是旁路观察与计算，**不修改原版金币的产生方式**。这是它与同工作区「超级五合dlc / 经济新生」（Harmony 接管原版 `gold` 槽）最本质的区别。

## 3. 生命周期与驱动循环

### 3.1 加载（`OnModLoad`）

1. `EconomyConfigCallbacks.RegisterLocales()` —— 注册设置页标签本地化
2. `EconomyConfigCallbacks.SyncFromModConfig()` —— 从 NML 配置同步到 `UnrestConfig` 单例
3. `RegisterEraTraits()` —— 注册时代/法典/国力国民特质（含独立图标；**失败只记日志，绝不让加载崩溃**）
4. `DecisionEvents.Load()` —— 解析 `events.json`（一次，fail-open 空池）
5. 挂 `EconomyTickRunner` 组件；`HistoryService.ClearHistory()`；`EconomyUI.Initialize()`

### 3.2 主循环（`EconomyTickRunner.Update`）

分两档节流，职责清晰：

| 频率 | 内容 |
|---|---|
| **每帧** | 性能采样 → 首帧装 4 处补丁 → 大地图快捷键读国 → `NationEngine.TickNativePlacement()`（原版建筑放置模式）→ `InheritanceEngine.Tick` → `UnrestEngine.SustainRebelWars()` → **消费后台统计结果** → `AnnualPipeline.Tick()` → `MemoryCleanupEngine.Tick` → UI 结算态 → 实时刷新节流 |
| **每 0.5 s** | 反射读游戏年份（`MapBox.map_stats.get_year`）→ 季度事件抽签（2/5/8/11 月）→ 语言变化检测 → 世界就绪守卫 |

**关键设计**：年份反射调用被节流到 0.5 s 一次（避免每帧 `Invoke` 开销）；快捷键解析只在配置字符串变化时做一次 `Enum.TryParse`（热路径只做 ordinal 字符串比较）。

### 3.3 年度触发链

~~~
年份变更
  → DataCollector.Collect()        [主线程：只采集数据，零计算]
  → TradeSimulationWorker          [后台线程：统计计算]
  → TryConsume() → FinishCycle()   [主线程]
  → AnnualPipeline.Start(year)     [分帧收尾]
  → 全部阶段完成 → WriteCycleSnapshot  [原子收尾：写快照 + 刷 UI]
~~~

自愈机制：若后台结果已就绪但 `_cyclePending` 未置位（历史遗留或工具按钮路径遗漏），下一帧会兜底置位，避免周期永久停摆。

## 4. 年度分帧管线（架构的心脏）

`Core/AnnualPipeline.cs` —— **17 阶段状态机**：

~~~
WealthTax → CycleModulator → Unrest → Policy → KingdomMonitor → SocialCrisis
→ Population → Spending → EraEvaluate → EraTick → Disaster → Banking → Bank
→ Nation → Events → Snapshot → Done
~~~

| 参数 | 默认 | 说明 |
|---|---|---|
| 帧预算 `FrameBudgetMs` | 4 ms/帧 | 超预算则剩余阶段下一帧继续 |
| 收尾窗口 `CycleWindowMs` | 2000 ms | 超窗口先**延窗**至硬上限 |
| 硬上限 | 5000 ms | 仍超时则按 **消费 → 银行 → 其他** 削减 |
| 削减铁律 | —— | **税收 / 再分配路径永不削减**（守恒） |
| `Snapshot` 阶段 | —— | **豁免帧切片**：所有经济阶段完成后同帧原子收尾 |

**不使用任何外部数据库**，全部状态写进**原版序列化通道**：

| 通道 | 键 | 内容 |
|---|---|---|
| `MapStats.custom_data` | `ce_world_id` | 世界 ID（第一通道） |
| 王国 `data` | `rb_world_id` | 世界 ID（第二通道） |
| 王国 `data` | `rb_hist` | GDP / 折线历史 |
| 王国 `data` | `rb_ev_stream` | 事件流（时间线） |
| 王国 `data` | `rb_nat_*` | 金库 / 政策槽 / 建筑记录 / 政绩 / 外交协定 |
| 王国 `data` | `rb_law_*` / `rb_ev_*` | 法典状态 / 待决事件与冷却 |

### 6.1 挂载点（手动 Harmony，非注解）

| 目标方法 | 时机 | 做什么 |
|---|---|---|
| `SaveManager.saveWorldToDirectory` | **Prefix** | 把内存状态同步进王国 `data`（**必须在此之前写世界 ID**，否则进不了档） |
| `SaveManager.saveWorldToDirectory` | Postfix | 写边车文件 |
| `MapBox.finishingUpLoading` | Postfix | **世界就绪锚点**（读档与新世界两条路径都走） |

### 6.2 两条踩坑教训（注释里写明，务必保留）

1. **注解补丁对预编译 DLL 不可靠** → 一律首帧手动 `harmony.Patch(...)`。
2. **`loadWorld` 的 postfix 时机太早** —— `loadData` 只把任务塞进 `SmoothLoader` 队列就返回，此时 `map_stats`/`kingdoms` 尚未恢复。所以读档恢复必须挂 `MapBox.finishingUpLoading`。
3. **世界 ID 必须走官方 `set/get`** —— `CustomDataContainer` 字段初始为 `null`（官方 `set()` 懒创建），直接索引 `custom_data_string[key]` 会 NRE 并被静默吞掉，键永远写不进存档 → 每次读档都被误判为「新世界」。

### 6.3 容错

任一环节异常则回退「本局记忆」（日志警告一次，**不阻塞游戏**）；世界身份用 `MapStats` 对象引用作为跨世界缓存失效信号，防止「world/管理器引用与数量都相同」时复用旧缓存而串档。

## 9. 配置与本地化

- `default_config.json`（12.7 KB）↔ `Models/UnrestConfig` 单例。模组加载时 `SyncFromModConfig()` **拉取一次**初始值；持久化由 NML 负责，`UnrestConfig` 不写文件。
- **命名约束**：`Services/ConfigCallbacks` 的**类名必须与 `default_config.json` 中 `Callback` 字段一致** —— NML 按简单类名跨程序集解析。
- 六语言：`ch.json` / `zh_tw.json` / `en.json` / `ru.json` / `ja.json` / `de.json`，动态加载；默认 `auto` 跟随游戏本体语言，游戏内切换语言会触发全 UI 刷新。

## 10. 事件系统

- 定义在 `events.json`（约 130 KB，346 事件 × 6 族），模组加载时解析一次，**fail-open**（解析失败退化为空池，不影响其余功能）。
- 一年四个触发点：2 / 5 / 8 / 11 月（`Date.getCurrentMonth()`），`EvaluateQuarter(year, q)` 自带同季度幂等。
- 待决 / 冷却 / 全局标记经 `rb_ev_pending` / `rb_ev_cooldown` / `rb_ev_lastGlobal` 随存档。
- 每局事件池随机（世界种子：约 68% 事件 + 变体互斥组 + 族倾向轮换）。
