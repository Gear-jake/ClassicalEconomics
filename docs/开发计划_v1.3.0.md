# ClassicalEconomics v1.3.0 开发计划

> 定稿日期：2026-09-03。本文件是执行蓝图（仅计划，未开始执行），覆盖四条主线：删除贸易模拟、补全中央银行家存档、修内阁年度自动刷新、UI 整体缩放（字体+按钮）。

## 0. 背景与调查结论

### 0.1 为什么删除贸易模拟（已确认“彻底删除”）
- **直接效果不可见**：贸易把金币在城市仓库间零和搬运（TradeSimulationWorker.ApplyTradeFlows），原版城市金币用处有限，玩家无感知；间接效果（顺差国民战斗特质、关税政策、银行传染）全被归因为“贸易”之外。
- **后台竞态（必须修的真实隐患）**：后台线程 `ComputeTrade` 违反“后台零字典访问”不变量——`NationEngine.IsMarketCity` 读 `_cityBuildings` 字典（主线程每帧写）、`NationDiplomacy.BilateralFlowMult` 读 `_pacts` 字典（外交按钮随时写），Dictionary 并发读写可致崩溃/死循环。
- **性能放大**：认领国家后每秒实时刷新会把贸易寻路（≤100 对 A* × ≤2048 步，主线程）从“每年一次”放大到“每秒一次”，约 20 倍频率。

### 0.2 为什么补全存档（已确认“补全中央银行家存档”）
- 现状只有法典落盘（rb_law_*，LawSave 补丁）。王室金库、认领国家、6 项政策、政绩记录、外交协定/好感、GDP 折线历史全部不持久化——读档后中央银行家玩法归零。
- 附带缺陷：读另一存档时 GDP 折线接上一局历史（串档）；读档不清 NationEngine 旧 id。

### 0.3 其他两个 bug
- 内阁不随年度更新：`EconomyUI.RefreshOverview()` 漏刷 CabinetWindow，内阁 `RefreshNow()` 仅按钮点击触发。
- 字体/按钮太小：字号散落 AddLine（6~13f ×79 处），按钮硬编码 28 高/12 字/86~120 宽。

## S0：UI 修复（先做，独立可交付）

### S0-1 内阁年度自动刷新
- 文件：`UI/EconomyUI.cs`、`UI/CabinetWindow.cs`。
- `EconomyUI.RefreshOverview(bool refreshCabinet)`：为 true 且 `CabinetWindow.Instance.IsVisible` 时调用 `RefreshNow()`。年度快照（WriteCycleSnapshot）、手动采集、热重载、语言切换传 true；**实时刷新（每秒）传 false**——防止每秒整页重建（含 GDP 图 ChartMeshGraphic）造成 GC 抖动。
- `CabinetWindow.RefreshNow()` 加 `_refreshing` 重入保护（年度刷新恰逢按钮触发时防双重 Destroy）。
- 更新 RefreshOverview 全部调用点（约 6 处：WriteCycleSnapshot/ManualCollect/RealTimeRefresh/Reload/语言切换等）。

### S0-2 UI 整体缩放（字体+按钮，玩家可调）
- 文件：`Models/UnrestConfig.cs`、`default_config.json`、`Services/ConfigCallbacks.cs`、`UI/CabinetWindow.cs`、`Core/KingdomWindowIntegration.cs`、四语 Locales。
- `UnrestConfig` 加 `UiScale`（默认 **1.2**，clamp 0.8~1.6）；`default_config.json` 加 `ui_scale`（TEXT）；`ConfigCallbacks` 加同步与 `OnUiScaleChanged` 回调（改后即时刷新可见内阁与摘要卡）。
- CabinetWindow 加 `Fs(size) = size × UiScale`，全部入口走 Fs：
  - AddLine（text,color,size）内部 size→Fs(size)；
  - AddRowButton：高 28→Fs(28)、字号 12→Fs(12)、宽度参数（86/90/100/120/56）→Fs；
  - NewRow：行高 28/30→Fs；
  - Tab 按钮（高 28、字 12）与外交列表行按钮（高 30、字 12）→Fs；
  - 直接 CreateText 处（国名 15f、外交行 11f 等）→Fs。
- 法律档位行本就 fill 均分布局（窗口窄时自动收缩），放大后不挤爆；固定宽行 3×120×1.2≈432f 在窗口宽度内，风险可控。
- `KingdomWindowIntegration` 原版窗口摘要卡：字号 11×scale，卡片 190×72 同步放大（上限 ~240×96，防挤爆原版窗口）。
- 四语加 `ui_scale` 键与描述；`tools/Test-ConfigDocs.ps1` 跟随。
- 范围仅内阁+摘要卡；HUD/富豪榜/事件窗本次不动（防连锁回归）。

## S5：存档补全（新 `Core/NationSave.cs`）

机制与 LawSave 相同：saveSave 前缀写 + loadSave 后缀读 + Harmony 手动 Patch + 首帧幂等安装（EconomyTickRunner 首帧 TryInstall），任一环节异常回退本局记忆。

**写入键（王国 data）**：

| 键 | 内容 | 格式 |
|---|---|---|
| rb_nat_treasury | 王室金库 | long 文本 |
| rb_nat_kingdom | 认领国 id | long 文本 |
| rb_nat_slot_{i} | 政策槽 | `kind:tier:startYear:totalSpent`（按 PolicyKind 枚举值存，改义不破坏存档） |
| rb_nat_buildings | 城市建筑记录 | `cityId:kind;...` |
| rb_nat_records | 政绩记录（环形 ≤RecordCapacity） | `year\|key\|amount;...` |
| rb_nat_pacts | 外交协定 | `id:tier;...` |
| rb_nat_goodwill | 外交好感 | `id:val;...` |
| rb_hist | GDP 折线历史 | `year:gdp:avg:gini:phase:cpi;...`（按存档年份截断） |

- `Services/HistoryService.cs` 加 Serialize/Restore（rb_hist 落盘+恢复），解决读另一存档串档。
- 读档恢复：每键独立 try-catch + 档位 clamp + 认领国存在性校验（已灭→清认领），失败回退本局记忆（警告一次不阻塞游戏）。
- 读档分支（年份回退>1）由 rb_hist 恢复覆盖内存历史；NationEngine 旧状态由 LoadPostfix 全量覆盖。

## 7. 验证点

**存档兼容**：
- 旧存档（1.2.1fix）：法典档位不错位（LawKeys/PolicyKeys 键位未动）；金库/认领新键首次写入。
- 新存档：读档后金库、认领国家、6 政策档位、建筑记录、政绩、外交协定/好感、GDP 折线全部恢复。

**游戏内**：
- 内阁挂机跨年自动刷新数据（无需点击）。
- 字号与按钮默认放大 1.2 倍，设置页 0.8~1.6 即时生效。
- HUD 无“贸易总额”行；概览无贸易份额榜入口；国民特质列表无“贸易顺差/逆差/货殖之国”。
- 中央政策页为 铸币/专卖；市场建筑提示“居民税基+10%”；外交页为“双边经济协定”。

**性能与稳定性**：
- 认领国家后每秒刷新不再有 A* 寻路；内阁不参与每秒重建。
- 后台线程零字典访问不变量恢复（ComputeTrade 及三个贸易乘数调用全部消失）。

## 8. 风险与回退

- 风险1：法典改义后效果变弱 → 通商惠工 Consumer/Happiness 加成补偿；如体验仍弱，后续版本调数值（单点参数）。
- 风险2：UI 缩放 1.2 后个别行挤爆 → 法律档位行已 fill 均分自适应；摘要卡有 240×96 上限；如仍有挤压，调 clamp 上限或放宽窗口默认尺寸。
- 风险3：存档键序列化超长（政绩/历史 100+ 年）→ 环形缓冲 ≤RecordCapacity、rb_hist 按年份截断；如王国 data 有键长限制，拆分多键。
- 回退：每个阶段独立可提交（S0 先行），任何阶段出问题可单独 revert，不影响已发布功能。
